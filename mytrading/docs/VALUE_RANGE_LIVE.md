# value_range 전략 실전 구현

백테스트로 검증한 규칙을 실전 코드에 옮긴 기록.
검증 기록은 `VALUE_RANGE_VALIDATION.md` 참조.

작성일: 2026-07-19

---

## ⚠️ 먼저 — 이전 문서의 수치는 대체되었습니다

`VALUE_RANGE_VALIDATION.md` 의 **CAGR +8.6%** 는 36종목 풀에서 나온 값인데,
그 풀 자체가 **데이터 수집 버그로 편향된 표본**이었음이 이후 밝혀졌습니다.

| 구분 | 종목 풀 | CAGR |
|---|---|---|
| 이전 (편향) | 36종목 | +8.6% |
| 편향 제거 | 75종목 | +5.7% |
| **편향 제거 + 현금 하한** | **75종목** | **+8.7%** |

자세한 내용은 아래 "데이터 커버리지 버그" 및 "현금 하한" 절 참조.

## 1. 데이터 커버리지 버그 (CFS → OFS)

### 증상

유니버스 76종목을 전수 판정하니 국면 "판정불가" 가 7종목.
부채·영업이익·배당은 모두 통과인데 국면만 실패했습니다.

파보니 공시일(`rcept_dt`)은 정상 조회되는데 영업이익 금액만 `None` 이었습니다.

```
DSR제강 2023  Q1~Q4: {'op': None, 'rcept': 2023-05-12 ...}   ← 보고서는 찾음
DSR제강 2025  Q1~Q4: {'op': 60.5, 'rcept': 2025-05-15 ...}   ← 2025부터만 정상
```

### 원인

`dart_data` 와 구버전 `collect_op.py` 가 **`fs_div="CFS"`(연결재무제표)만 조회**하고 있었습니다.
**종속회사가 없는 소규모 기업은 연결재무제표를 작성하지 않고 개별(OFS)만 제출**하므로
빈 결과가 돌아왔던 것입니다.

실측 확인:

| 종목 | CFS(연결) | OFS(개별) |
|---|---|---|
| DSR제강 | 빈 결과 | 234.9억원 |
| 삼일기업공사 | 빈 결과 | 31.0억원 |
| 고려신용정보 | 130.7억원 | 117.1억원 |

### 수정

`get_quarterly_op` / `get_eps` 에 **CFS 우선 → 빈 결과면 OFS 폴백**을 추가했습니다.
둘 다 있으면 CFS 가 그룹 전체 실적이므로 우선입니다.

### 결과

판정불가 4종목이 모두 정상 판정으로 복구되었습니다.

```
DSR제강        판정불가 → 평범     (YoY +8.6%)
삼일기업공사    판정불가 → 정점통과  (YoY -32.7%)
스튜디오삼익    판정불가 → 침체     (YoY -56.4%)  ← 실제로 나쁜 종목, 정당한 배제
감성코퍼레이션   판정불가 → 성장     (YoY +38.3%)
고려신용정보    평범 → 평범 (유지)               ← 대조군
```

### 파급 — 백테스트 표본이 편향되어 있었다

이 버그 때문에 백테스트 종목 풀이 **연결재무제표를 쓰는 기업(= 종속회사를 둔
비교적 큰 회사)으로 자동 선별**되어 있었습니다. 36~41종목이었던 이유입니다.

재수집 후 **75종목**으로 늘었고, 성과 수치가 전면 재평가되었습니다.

## 2. 데이터 재수집

세 데이터가 모두 필요합니다. 수집 후 76종목 중 75종목이 백테스트 가능해졌습니다.

| 데이터 | 수집 경로 | 결과 |
|---|---|---|
| 주가 일봉 | `daily_update.py --force` (universe 전체 자동) | 75/76 |
| 분기 영업이익 | `mytrading/collect_op.py` (신규) | 76/76 |
| 배당 이력 | `mytrading/collect_div.py` (신규) | 76/76 |

### `mytrading/collect_op.py`

구버전 `~/collect_op.py` 는 DART 조회 로직을 자체 복제하고 있어 CFS 버그가
양쪽에 존재했습니다. 신규 스크립트는 **`dart_data.get_quarterly_op` 를 재사용**하므로
폴백이 자동 적용되고 코드 경로가 하나로 통일됩니다.

```
KIS_MODE=prod uv run python mytrading/collect_op.py --refresh --sleep 0.3
```

### `mytrading/collect_div.py`

배당 이력의 원천은 DART 가 아니라 **`ksdinfo_dividend`(한국예탁결제원 배당정보)** 입니다.
`record_date`(배당기준일) + `per_sto_divi_amt`(주당배당금) 를 1년 단위로 나눠 조회합니다.

```
KIS_MODE=prod uv run python mytrading/collect_div.py --refresh --sleep 0.3
```

⚠️ `ksdinfo_dividend` 는 KIS 예제 폴더에 있어 직접 import 가 안 됩니다.
`import mytrading.finance_data` 를 먼저 해서 sys.path 등록 부수효과를 이용합니다.

## 3. 성과 재평가 (75종목)

### 종목 풀 확대의 영향

| 연도 | 36종목 | 75종목 |
|---|---|---|
| 2021 | +8.1% | +10.6% |
| 2022 | +3.1% | **-17.6%** |
| 2023 | +17.6% | +8.7% |
| 2024 | -1.8% | -6.6% |
| 2025 | +14.0% | +23.8% |
| 2026 | +0.8% | +15.2% |
| **CAGR** | **+8.1%** | **+5.7%** |

2022년이 결정적으로 나빠졌습니다.

### 2022년에 무슨 일이 있었나

```
2022-01  보유  7종목  현금 33.6%   자산 1,105만
2022-02  보유 10종목  현금  5.9%   ← 한 달 만에 소진
2022-06  보유 11종목  현금  0.7%   ← 완전 고갈
2022-07  자산 961만 (급락)
2022-10  자산 922만 (최저)
```

**하락장 초입에 자금을 다 써버렸습니다.**
2월에 이미 만석, 6월엔 현금 0.7%. 그 뒤 시장이 더 빠졌지만 물타기도 저점매수도
할 수 없었습니다.

하락장에서는 여러 종목이 동시에 52주 저점+5% 에 진입하므로 신호가 쏟아지고
자금이 순식간에 소진됩니다. **종목 풀이 클수록 심해지는 value 전략의 구조적 약점입니다.**

## 4. 현금 하한 (핵심 발견)

### 스윕 결과

| 현금 하한 | CAGR | 평균 보유 | 평균 현금 |
|---|---|---|---|
| 0% | +5.7% | 9.6종목 | 11.1% |
| **10%** | **+9.2%** | 9.3종목 | 15.6% |
| 20% | +8.4% | 7.8종목 | 25.5% |
| 30% | +6.5% | 6.4종목 | 34.6% |

### 견고성 확인 — 2022년에만 맞춘 것이 아니다

| 연도 | 하한 0% | 하한 10% | |
|---|---|---|---|
| 2021 | +10.6% | +10.7% | ≈ |
| 2022 | -17.6% | -8.4% | 개선 |
| 2023 | +8.7% | +12.0% | 개선 |
| 2024 | -6.6% | **+7.9%** | 마이너스 → 플러스 |
| 2025 | +23.8% | +27.6% | 개선 |
| 2026 | +15.2% | -0.9% | 악화 (부분 연도·미청산 평가손) |
| **누적** | **+31.8%** | **+54.9%** | |

**6년 중 5년에서 개선**되었습니다.

### 왜 효과가 있나

현금 0% 에서는 **-30% 물타기 신호가 떠도 돈이 없어 실행하지 못했습니다.**
백테스트가 검증한 물타기의 이득이 자금 부족으로 무력화되어 있었던 것입니다.

현금을 남기면
- 하락장 초입에 전량 소진하지 않아 더 낮은 가격에 살 여력이 생기고
- 물타기가 실제로 작동합니다

이것은 앞서 6번 실패한 "타이밍 정교화" 와 **범주가 다릅니다**.
매수 조건이 아니라 **자금 관리**를 바꾸는 것입니다.

### ⚠️ 정확한 값은 정할 수 없다

구현 방식을 바꾸자 같은 "10% 하한" 이 +9.2% 와 +6.2% 로 3%p 차이가 났고,
자본금에 따라 10/15/20% 의 순서가 뒤집혔습니다.

```
1,000만원:  10% +6.2%  <  15% +7.7%  <  20% +8.7%
2,000만원:  10% +8.7%  >  15% +6.9%  <  20% +8.0%   ← 비일관
```

**견고하게 남는 결론은 "현금을 0까지 소진하지 말 것" 하나뿐입니다.**
config 의 `cash_floor: 15` 는 10~20 범위에서 임의로 고른 값이며,
이 숫자를 근거로 다른 판단을 하면 안 됩니다.

## 5. 자산 규모 검증

2,000만원으로 돌려도 규칙이 그대로 작동합니다.

| 자본금 | 평균 슬롯 | 평균 보유 | CAGR (최선값) |
|---|---|---|---|
| 1,000만원 | 9.0개 | 8.5종목 | +8.7% |
| 2,000만원 | 19.0개 | 16.6종목 | +8.7% |

슬롯 상한 20 은 2,000만원 구간에서 실제로 걸리기 시작하며,
CAGR 이 동등하므로 **상한 20 을 유지해도 됩니다.**

## 6. 실전 구현

### 국면 게이트 (`stock_eval.py`)

`style == "value_range"` 일 때만 `is_buyable_phase()` 를 `buy` 조건에 AND 결합합니다.
침체·판정불가면 매수 보류. `passed`(종목 품질)는 건드리지 않습니다.

```
- 재무 O / 차트 O / 국면 평범  →  ★매수후보
- 재무 O / 차트 O / 국면 침체 ✗매수보류
```

### 국면 판정 캐싱 (`finance_data.py`)

`_judge_phase` 는 종목당 DART 를 30회 호출합니다. `(종목, 기준일)` 캐시를 추가했습니다.

```
1회차: 6.10초  →  2회차: 0.00초
```

### 매도 규칙 (`order_pace.py`)

**52주 고점 기준 매도를 제거**했습니다. 내 매수가와 무관해 손실 구간에서도
매도 신호가 나서 백테스트와 어긋나기 때문입니다.

대신 평단 기준 `position_action(pnl_percent, already_averaged)` 를 신설했습니다.

```
+15% 이상   →  익절 (전량)
-50% 이하   →  손절 (전량)
-30% 이하   →  물타기 1회 (이미 물탔으면 보류)
그 외       →  보유
```

⚠️ 손절(-50%)이 물타기(-30%)보다 **우선**입니다. 순서 주의.

### 물타기 1회 제한 (`position_state.py`)

계좌 잔고에는 "이미 물탔는지" 정보가 없어 별도 상태 파일로 추적합니다.

⚠️ **현재 설계는 주문 체결 훅을 전제로 하는데 이 시스템에는 자동 발주가 없습니다.**
계좌 수량 변화로 자동 감지하는 방식(최초 보유 시 `entry_qty` 기록 →
현재수량 > entry_qty 면 물타기로 판단)으로 **재설계가 필요합니다.**

### 매수 금액 산정 (`position_sizing.py`)

```
예산      = 계좌 총평가금액 × allocations.yaml 카테고리 비중(%)
투자가능  = 예산 × (1 - cash_floor%)
슬롯수    = clamp(투자가능 ÷ min_unit, 1, max_slots)      내림
종목당    = 투자가능 ÷ 슬롯수
수량      = 종목당 ÷ 현재가                              1주 단위 내림
```

설정 (`mytrading_config.yaml` → `position_sizing`)

| 항목 | 값 | 비고 |
|---|---|---|
| `min_unit` | 1,000,000 | 슬롯당 최소 금액 |
| `max_slots` | 20 | 상한 도달 후엔 종목당 금액이 커진다 |
| `cash_floor` | 15 | **최적값 아님** — 10~20 범위 임의 선택 |
| `min_order_amount` | 300,000 | 미만이면 매수 건너뜀 |
| `allow_below_min_unit` | true | 투자가능액이 100만원 미만이어도 소액 매수 |

자산 규모별 산출 예시 (moderate 20% 기준)

| 총평가 | 예산 | 투자가능 | 슬롯 | 종목당 |
|---|---|---|---|---|
| 5,000만원 | 1,000만 | 850만 | 8 | 106만 |
| 1억원 | 2,000만 | 1,700만 | 17 | 100만 |

백테스트의 "1,000만원 × 10슬롯" 은 실전에서 **총평가 5,000만원 구간**에 해당합니다.

### 배당 프리미엄

`mytrading_config.yaml` 의 배당 프리미엄을 코스피 0.5 → 0.0, 코스닥 1.0 → 0.0 으로
조정했습니다 (백테스트에서 국고채+0%p 가 최적).

### 매매 계획 연결 (`trade_plan.py`)

```
미보유  →  52주 저점+buy_zone% AND 국면OK  →  금액·수량 산정  →  매수
보유    →  position_action(평단 대비 손익률)  →  익절/물타기/손절/보유
```

- 잔고 스냅샷은 실행당 1회만 조회 (모듈 전역 캐시)
- 국면 판정 실패 시 보수적으로 매수 보류 ("모르면 안 산다")
- 금액 산정 실패·미달 시 `action` 을 `hold` 로 되돌리고 사유를 기록

동작 확인

```
모토닉  hold
    52주 최저가 +4.3% (저점 근처, ≤5%) → 매수 보류: 주문금액 0원 < 최소 300,000원
```

## 7. 유니버스 전수 판정 (`check_universe.py`)

76종목을 재무 3관문 + 국면 + 차트로 일괄 판정합니다.

```
KIS_MODE=prod uv run python check_universe.py            # 전체
KIS_MODE=prod uv run python check_universe.py --limit 10 # 시험
```

결과 (2026-07-19 기준, OFS 폴백 적용 전)

| 판정 | 종목 수 | 의미 |
|---|---|---|
| ★매수 | 5 | 재무·국면·가격 모두 통과 |
| 대기(가격) | 40 | 종목은 합격, 아직 저점 근처가 아님 |
| 탈락(재무) | 23 | 22건이 영업이익 미달 |
| 탈락(국면) | 8 | 침체 1 + 판정불가 7 |

**45종목(5+40)이 재무 3관문을 통과**했습니다.
현재 moderate 승인 종목이 1개뿐이라 슬롯 10~20개를 활용하지 못하고 있는데,
이 45종목을 승인해두면 저점 진입 시 자동으로 매수 신호가 뜹니다.

부채·배당은 거의 다 통과합니다(유니버스 편입 시 이미 배당 스크리너를 거침).
**실질적으로 영업이익이 유일한 필터**입니다.

## 8. 시스템 구조 (실측 확인)

- **자동 발주가 없습니다.** KIS 주문 API(`order_cash` 등)는 `legacy/` 에만 있고
  `mytrading/` 에서는 쓰지 않습니다. `notify_order_*` 를 호출하는 곳은
  `runners/test_order.py` 하나뿐이고, 봇 커맨드에도 매수/매도 실행이 없습니다.
  **봇이 신호를 알리고 주문은 직접 체결하는 조언형 구조입니다.**
- `build_plan` 은 **Approval 상태 종목만** 계획에 넣습니다 (설계 의도).
- `slice_pct` 는 실제 주문 실행에 연결되어 있지 않습니다 (소비처가 `newsletter_ai.py` 뿐).
