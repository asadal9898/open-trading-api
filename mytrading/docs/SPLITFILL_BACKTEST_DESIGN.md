# 분할 매수/매도 백테스트 설계 (1-b 선행 작업)

> 작성: 2026-06 / 목적: 1-b(실제 분할 주문) 전에 "분할이 일시매수보다 나은가"를 백테스트로 검증
> 이 문서는 다음 세션의 시작점. 여기 설계대로 구현하면 됨.

---

## 0. 배경 — 왜 별도 시뮬레이션인가

기존 백테스터(`kis_backtest`)의 RuleBuilder 메서드를 확인한 결과:
```
buy_when, sell_when      → 신호 (언제 사고 파나)
stop_loss, take_profit, trailing_stop → 청산 규칙
max_position             → 최대 보유 비중
```

**전부 '신호 타이밍' 중심.** "정해진 금액을 며칠에 나눠 집행한다"는 분할 매수(DCA) 개념이 없음.
→ 기존 compare_strategies 로는 분할 비교 불가.
→ **별도 분할 시뮬레이션(splitfill_sim)** 을 새로 만들어야 함 (갈래 B).

핵심 구분:
- 기존 백테스터 = "언제 진입/청산하나" (신호)
- 분할 시뮬레이션 = "한 번 진입을 어떻게 쪼개나" (집행 방식)
두 개는 다른 차원. 분할은 신호가 아니라 **집행(execution)** 문제.

---

## 1. 무엇을 검증하나

질문: **"목표 금액을 한 번에 살까, 나눠 살까? 나누면 어떻게?"**

비교 대상(집행 방식):
- **lump (일시매수)**: 목표액을 첫날 전액 매수 — 기준선
- **DCA-N-d (정액 분할)**: 목표액을 N회로 나눠 d일 간격 매수
  - 예: 3회 × 1일, 3회 × 3일, 5회 × 1일, 5회 × 5일, 10회 × 1일
- (선택) **dip-buy (하락 시 매수)**: 가격이 X% 빠질 때만 분할 집행 — 나중에

매도도 동일 구조로 (분할 매도) 추후. 우선 매수부터.

---

## 2. 평가 지표

각 집행 방식을 과거 데이터로 돌려 비교:
- **평균 진입가** (낮을수록 유리) — 분할의 핵심 기대효과
- **최종 평가손익** (매수 후 기간말 평가 / 또는 특정 보유기간 후)
- **변동성/MDD** (분할이 진입 변동성을 줄이는가)
- **현금 노출 기간** (분할은 돈이 늦게 들어감 = 기회비용)

가장 중요한 건 **평균 진입가 + 그 후 수익률**. "분할하면 평균단가가 낮아지나? 그게 수익으로 이어지나?"

---

## 3. 어떤 데이터로

- **종목**: universe 종목 (삼성전자, SK하이닉스, 고려신용정보, 모토닉, KODEX S&P500)
- **기간**: 여러 시장 국면 포함 (상승장/하락장/횡보장 각각) — 분할은 국면 따라 유불리가 갈림
  - 상승장: 일시매수가 유리할 가능성 (빨리 살수록 좋음)
  - 하락장/횡보: 분할이 유리할 가능성 (평단 낮춤)
  - → **국면별로 나눠 봐야** 결론이 정확함
- **데이터 소스**: 기존 prefetch_data / data_manager 의 캐시된 일봉 활용 (API 0회)

---

## 4. 구현 스케치 (다음 세션)

### 4-a. splitfill_sim.py (새 모듈)
```
입력: 종목, 기간, 목표금액, 집행방식(lump / DCA N회 d일)
처리:
  - 과거 일봉 가격 시계열을 가져옴 (data_manager 캐시)
  - 집행 방식대로 매수 시점/금액 분배
    · lump: 첫날 전액
    · DCA: N회로 분할, d일 간격, 각 회차 그날 종가로 매수
  - 각 회차 체결가 기록 → 평균 진입가 계산
  - 진입 완료 후 ~ 기간말 평가손익 계산
출력: {방식, 평균진입가, 보유주수, 평가손익%, MDD 등}
```

### 4-b. compare_splitfill.py (비교 러너)
```
- 같은 종목/기간에 여러 집행방식(lump, DCA 3/5/10회, 간격 1/3/5일) 돌림
- 표로 비교 + CSV 저장 (compare_strategies 패턴 재사용)
- 국면별(상승/하락/횡보 기간)로 나눠 반복
```

### 4-c. 결과 → 결정
- 어떤 분할 방식이 어떤 국면에서 유리한지 정리
- **결정**: 1-b 에서 쓸 분할 방식 (예: "3회 × 2일" 또는 "국면 무관 일시매수")
- 결론을 allocation_plan / 1-b 구현에 반영

---

## 5. 주의 / 원칙

- **검증 없이 분할 방식 확정 금지** (차영석 원칙: 자동매매는 백테스트로 검증된 규칙만)
- 분할이 항상 유리한 게 아님 — 상승장에선 일시매수가 나을 수 있음. 데이터로 확인.
- 거래비용(수수료/세금) 포함해서 계산 — 분할은 거래 횟수가 늘어 비용 증가
- 시뮬레이션은 '과거가 미래를 보장하지 않음' 전제. 참고자료로.
